# 0002. Lean rebuild of Passui on Zag, tsdown and a separate icon package

**Date**: 2026-11-12
**Status**: In Progress

## Summary

Passui becomes a light, shadcn shaped library with an Apple 2026 look. Each component is small, uses a Zag.js state machine for accessibility, and costs the consumer only what they import. Icons move to a new `@passui/icons` package. Libraries are compiled with tsdown, and the repo is run by Bun, Turborepo and Biome. The old library is replaced alongside, not all at once, and the block level pieces leave core.

## Structure

- [0003 Overlays](0003-overlays.md): Dialog, Alert Dialog, Sheet, Drawer, Popover, Tooltip and Dropdown Menu on Zag machines. Supports build plan step 4.

## Requirements

**User stories**:
- As a Pherus app developer, I want to import one component and pay only for that component, so that my app stays small.
- As a developer who knows shadcn, I want familiar names and shapes (`Card`, `Badge`, `Dialog`), so that I do not read a translation table.
- As the maintainer, I want one simple build and one lint tool, so that the repo is easy to change.

**Acceptance criteria**:
- **AC-1**: `Button` costs 2 KB gzip or less. The measure is the entry's own code plus bundled dependencies (Zag counted as a dependency), with React and `@passui/*` external and CSS excluded. Every wave 1 component gets a budget in `size-budgets.json` when it is built, and the rewritten `bun run size:check` fails CI on any growth over budget.
- **AC-2**: Each component has an allow list of modules it may import (its own Zag machine only, never an icon pack or Motion unless listed). A Turbo task builds each entry with tsdown and fails if anything outside the allow list appears in the graph.
- **AC-3**: `@passui/icons` is its own package. Each icon is its own subpath and the package is `sideEffects: false`. Each icon is one SVG with a primary and a secondary group, rendered with `tone="mono"` or `tone="duo"` (secondary styled through `--icon-secondary`). Animation is one `@passui/icons/styles.css` with `spin`, `pulse` and `draw`, driven by data attributes and disabled under `prefers-reduced-motion`. The icon list is frozen in `icons.manifest.json` from this repo plus Pass and Accounts, and a test checks the exports against it. Icons are redrawn, not copied from Hugeicons.
- **AC-4**: Every interactive wave 1 component is driven by a Zag machine, or is a native element listed in a Zag less table in `packages/ui/AGENTS.md`. Each works by keyboard, exposes correct roles, names and states, and has a `vitest-axe` test through one shared test helper. Contrast is covered by tokens, not jsdom.
- **AC-5**: `Sheet` and `Drawer` use the curve `cubic-bezier(0.32, 0.72, 0, 1)`, drag to dismiss with momentum, and scale the page behind. Zag drawer owns swipe release and snap decisions (see [0003](0003-overlays.md)); Passui's page scale and progress mapping are pure functions with unit tests. Playwright with touch emulation checks dismiss and mid animation reversal, where the sheet position stays within 1 px on reversal. Reduced motion disables the scale and spring. A check on a real iOS and Android device gates the release.
- **AC-6**: Spring values, curves and durations are plain data in `@passui/tokens/motion`. Passui machine and math files hold only data and pure functions, enforced by a Biome import restriction (no React, no DOM). Zag adapters live in the components. A Rust port can copy the data and math as is.
- **AC-7**: `@passui/react`, `@passui/tanstack`, `@passui/tokens` and `@passui/icons` publish compiled ESM and `.d.ts` built by tsdown, with `"use client"` preserved, shared chunks on, and `exports` generated by tsdown. No raw `.tsx` is published and `scripts/build-types.mjs` is deleted.
- **AC-8**: The repo uses Bun to install and run, Turborepo to order tasks, and Biome for lint and format. `bun run check` runs Biome and typecheck only. Docs generation is not part of `check`.
- **AC-9**: `biome.json` lists only paths that exist in this repo, has `organizeImports` on, and treats accessibility rules as errors. Vitest and TypeScript versions are pinned once at the root.
- **AC-10**: Wave 1 components use shadcn names as the primary export, with named exports per part (`Card`, `CardHeader`, `CardTitle`). A simple component is a single file of 150 lines or fewer.
- **AC-11**: The block level pieces (`locale-switcher`, `conversation`, `stat-tile`, `wake-slider`, `swatch-picker`, `view-controller`, `content-view`) are gone from `@passui/react` after one deprecation release.
- **AC-12**: New components take the main subpaths. Old ones move to `./legacy/*` marked `@deprecated` in JSDoc, with a mapping table in the CHANGELOG. They are deleted in `0.3.0`.
- **AC-13**: Compiled classes are visible to Tailwind. `@passui/tokens/styles.css` includes the `@source` line for `@passui/react`, and the CLI templates and `www` import it. A test generates CSS from a sample app and checks a `Button` class is present.
- **AC-14**: Publishing is ready before first release: `@passui/icons` is in `publish.yml` with its npm trusted publisher, and Bun `catalog:` ranges resolve in the packed tarballs (`publish:check`). React 19 is the only supported React.
- **AC-15**: `www` has an SSR smoke test for overlay components (Zag ids and hydration under TanStack Start). Its props tables are read from built `.d.ts` at `www` build time only.

## Decision

**Chosen option**: Option 2: Strangler rebuild on Zag, tsdown and an icons package.

Build the new library next to the old one, ship it in waves, then delete the old exports. The layers are:

| Layer                  | Package            | Contains                                                                       | Weight rule                                                              |
| ---------------------- | ------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| Tokens and motion data | `@passui/tokens`   | Theme CSS, type scale, hairlines, blur, tap states, spring and curve constants | CSS and data only, no runtime                                            |
| Icons                  | `@passui/icons`    | Mono and duo icons, CSS animation, one subpath per icon                        | No dependencies beyond React                                             |
| Components             | `@passui/react`    | Wave 1 components, Zag machines per feature                                    | `@zag-js/react` plus only the machines a component uses. Motion optional |
| Integrations           | `@passui/tanstack` | Form, table, router, query wrappers                                            | Peers only for what the consumer uses                                    |
| Setup                  | `@passui/cli`      | Project starters                                                               | Unchanged except the template tooling                                    |

**Foundation**: Zag.js machines supply focus, dismissal, positioning, typeahead and roles. Passui supplies the look and motion. The owner rule against Base UI and shadcn runtime primitives stays; Zag is headless logic, not components.

**Motion**: the sheet curve and background scale use the values from Vaul (not a Vaul dependency), and drag momentum and snap points come from `@zag-js/drawer` ([0003](0003-overlays.md)). Springs use the CSS `linear()` easing generated from stiffness, damping and mass stored in tokens. Motion is an optional peer, used only by shared element morphs (`layoutId`).

**Visuals**: Tailwind v4 utilities and tokens carry the translucent blur, hairline border and tap highlight, following the Konsta patterns for iOS. State is styled through data attributes (`data-open`, `data-pressed`, `data-starting-style`, `data-ending-style`).

**Build and repo**: tsdown builds each library package from one small config. Vitest runs tests. Biome lints and formats. Turbo orders `build`, `typecheck`, `test`. Vite stays only inside `www`, because TanStack Start is a Vite plugin.

**Names**: shadcn names are primary. SwiftUI names survive only where shadcn has no equivalent (`Stepper`, `SegmentedControl`).

**Implementation skills**: `shadcn` (`.claude/skills/shadcn/`) · `tanstack` (`.claude/skills/tanstack/`) · `goey-toast` (`.claude/skills/goey-toast/`)

## Key invariants

- A component file imports only React, tokens, its own Zag machine, `cx`, and the shared helpers `render`, `presence` and `portal`. It never imports another component's internals, an icon pack or Motion directly.
- Icons are passed in by the consumer or imported from `@passui/icons`. No component embeds a default icon pack.
- No scrollbar chrome. Base styles hide it while scrolling still works.
- Machine files and motion constants contain no React, DOM or Tailwind.
- A new dependency needs a size budget entry before it merges.

## Build plan

Order is Tracer Bullet (no approach is recorded in `AGENTS.md`, so this follows the default for production work). Each thread goes end to end before the next widens it.

0. **Pre step.** Verify the current Zag version and React adapter API, and record them. Needed before any budget. Satisfies **AC-1**, **AC-4**.
1. **Tooling thread.** Pin shared versions with a Bun `catalog` at the root. Clean `biome.json` and turn on `organizeImports`, accessibility errors and the machine import restriction. Simplify `turbo.json`. Add tsdown configs to tokens, react and tanstack. Delete `build-types.mjs` and `check-packages.mjs`, drop the docs gate from `check`, and rewrite `size:check`. Satisfies **AC-6**, **AC-7**, **AC-8**, **AC-9**.
2. **Motion data.** Add spring, curve and duration constants to `@passui/tokens/motion` with matching CSS variables, and the `styles.css` `@source` line. Satisfies **AC-6**, **AC-13**.
3. **Button thread.** Rebuild `Button` end to end: shadcn name, Apple look, data attribute states, under 2 KB gzip, test, `www` page, budget entry, allow list test, legacy move to `./legacy/button` with `@deprecated`. This proves the whole pipeline. Satisfies **AC-1**, **AC-2**, **AC-10**, **AC-12**, **AC-13**.
4. **Overlay thread** (blocked on the overlays child spec). `Dialog`, `Alert Dialog`, then `Sheet` and `Drawer` with native Vaul physics, then `Popover`, `Tooltip`, `Dropdown Menu`. Zag machines, interruptible, axe tests, SSR smoke test. Satisfies **AC-2**, **AC-4**, **AC-5**, **AC-10**, **AC-15**.
5. **Form thread.** `Field`, `Label`, `Input`, `Input Group`, `Textarea`, `Checkbox`, `Switch`, `Radio Group`, `Toggle`, `Toggle Group`, `Slider`, `Select`, `Combobox`, `Command`, `Input OTP`. Satisfies **AC-1**, **AC-2**, **AC-4**, **AC-10**.
6. **Display and navigation thread.** `Card`, `Badge`, `Avatar`, `Alert`, `Separator`, `Skeleton`, `Spinner`, `Kbd`, `Progress`, `Tabs`, `Accordion`, `Collapsible`, `Breadcrumb`, `Pagination`, `Button Group`, `Toast`. Satisfies **AC-1**, **AC-2**, **AC-4**, **AC-10**.
7. **Icons thread** (blocked on the icons child spec). Freeze `icons.manifest.json` from this repo plus Pass and Accounts, create `@passui/icons` in `mono` and `duo` with CSS animation, add it to `publish.yml` and the npm trusted publisher, switch `@passui/react`, `@passui/tanstack` and `www`, then remove Hugeicons. Satisfies **AC-2**, **AC-3**, **AC-14**.
8. **Docs thread.** `www` reads props tables from built `.d.ts` at build time and deletes `generate-react-api.mjs`. Satisfies **AC-15**.
9. **Integrations thread.** Move `@passui/tanstack` to the new components and icons, with peers only. Satisfies **AC-2**, **AC-7**.
10. **Strangler close.** Remove the block level pieces, write the CHANGELOG mapping, migrate `www`, publish `0.2.0`, then delete `./legacy/*` in `0.3.0`. Satisfies **AC-11**, **AC-12**, **AC-14**.
11. **Waves 2 and 3** follow as separate specs, one per group.

## Migration plan

**Strategy**: strangler. New components ship next to the old ones, wave by wave.
**Phases**:
1. `0.2.0`: new wave 1 exports and `@passui/icons` ship. Old exports are marked deprecated and still work.
2. Pherus apps (Pass, Accounts) and `www` move to the new exports using the CHANGELOG mapping.
3. `0.3.0`: old exports and the block level pieces are deleted.
   **Rollback**: pin Pherus apps to the last `0.1.x` release. Each phase is a separate npm version, so a bad one is replaced by the next patch, since npm versions cannot be overwritten.
   **Risks**: Pherus apps lag and keep the old exports alive; sheet physics feel wrong on real devices; Zag API changes between minors.

## Consequences

**Positive**:
- A consumer pays only for imported components. Button's budget goes from 12 KB to a 2 KB target (AC-1, not yet measured).
- Accessibility becomes a tested contract from Zag instead of hand rolled hooks.
- The repo has fewer scripts and one build path, so it is easier to change.
- Motion constants and machines are plain data, ready for a Rust port.

**Negative / tradeoffs**:
- A large rewrite of about 40 components. It takes many releases and the old and new libraries both ship in the interim.
- Breaking changes for Pherus apps, with a migration table to follow.
- Zag adds its own API surface to learn, and its machines must be tracked as they change.
- Dropping `tailwind-merge` means consumers cannot override a component class by order alone. They use data attributes and variants.
- A native Vaul port needs careful testing on real touch devices.

**Neutral**:
- Vite remains in `www` and as a Vitest dependency.
- Icons are a new package to version and publish. Add it to `publish.yml` and npm trusted publishers.
